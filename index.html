Листы КМД по эталонам

По выбранному модулю на фасаде — лист модуля, лист панели, листы профилей. Раскладка и шаблоны видов как в эталонных чертежах офиса.

Пилот принят — проверены типовой, угловой, горизонтальный, парапетный, узкий и внутренний угловой модули.

Эффект по времени

Считаем 108 комплектов — по одному эталону на каждый тип модуля (Family + Type). Экземпляры с одинаковым типом (например, М-1 × 50) повторяют уже отработанный комплект; в сравнении «ручная разработка vs плагин» участвуют типы, а не 656 отдельных разработок.

Один комплект = лист модуля + лист панели + листы профилей + цепочки размеров + при необходимости смена ориентации видов (без пересоздания листа).

Зачем в статистике 656 экземпляров?

656 — масштаб монтажа на фасадах: столько раз модуль стоит на здании. Для КМД разрабатываем 108 эталонов по типам. После первого комплекта на тип остальные экземпляры того же типа получают листы быстрее (Replace / повторный прогон), но в «полную ручную разработку» их не умножаем.

Возможности плагина

Лист модуля (В9 / В20)

  • Фасад, разрезы по стойкам и ригелям, рама, изометрия
  • Плоский и угловой сценарий

Лист панели (В10 / В21)

  • Виды оболочки спереди и сзади, разрезы
  • Отдельный сценарий — не затирает лист модуля

Листы профилей (В11–В12 / В22–В25)

  • Изоляция стоек и ригелей, crop по эталону
  • Угловые — фиксированные пресеты по AnalyzeSheet

Цепочки размеров

  • Отдельная команда на ленте — база → центры деталей по стороне вида
  • Не блокирует выпуск листов; ускоряет финальную простановку

Ориентация видов

  • Поворот одного вида (90° / 180°) без Replace всего листа
  • Экономит повторный выбор модуля, разрезы и скрытие деталей на другом фасаде

Replace и привязка к модулю

Чертеж живой: правки геометрии в модели Revit автоматически попадают на уже созданные виды — это базовая функция Revit, плагин её не отменяет. ModuleId нужен для учёта листов плагином (какой экземпляр — «владелец» комплекта), а не для «заморозки» чертежа.

Модель изменилась — чертёж обновится?

Да, для того экземпляра, чью геометрию вы правите: виды на его листе перестраиваются вместе с моделью. Replace для этого не нужен — достаточно обычной работы в Revit.

Replace — только когда нужно пересобрать комплект: новые разрезы (добавились стойки/ригели), смена ориентации фасада, сломалась изоляция или crop, нужен чистый прогон сценария.

Правка типа vs правка одного экземпляра

Изменили тип М-1 (Family Type) — обновятся все 50 экземпляров в модели, и все уже выпущенные листы М-1 покажут новую геометрию (Revit).

Изменили один экземпляр на втором фасаде — меняется только он; его лист (если есть) обновится. Остальные 49 экземпляров М-1 в модели не тронуты — у них своя геометрия и, возможно, свои листы.

Листы не появятся сами на всех М-1, если вы выпускали комплект только для одного экземпляра — для каждого нужен свой прогон плагина. Replace на одном экземпляре не пересоздаёт листы на соседних.

Привязка (ModuleId)

Служебная метка: какой экземпляр модуля «владеет» листом. Нужна Replace, поиску дублей и отчёту покрытия.

Создание

Выбираете модуль на фасаде → сценарий → лист. Повтор для того же экземпляра — «заменить или создать новый».

Replace

Пересборка вида и листа с нуля у выбранного экземпляра — не для каждой правки модели, а когда изменилась структура комплекта.

Опорные плоскости — почему так

Одно семейство профиля для стойки и ригеля. Revit не может дать разные «роли» одному имени на разных экземплярах — поэтому разделение по уровню модели и ориентации.

ПлоскостьГдеСмысл
profil vertikalnyi centr профиль (nested) Вертикальная режущая плоскость → стойка, если нормаль согласована с шириной модуля
profil gorizontalnyi centr рама / модуль Уровень ригеля → высота разреза + поиск FI ригеля
Одно семейство профиля vs два (для спецификации)

Одно семейство — в ведомости одна строка на тип сечения (H20, H21…). Роль стойка/ригель определяет плагин при выпуске листов.

Два семейства — спецификация не «ломается», но дублирует учёт одного проката и усложняет контроль: не видно, куда исполнитель поставил деталь, до выпуска чертежей. Скорость выгрузки профилей не зависит от числа семейств.
